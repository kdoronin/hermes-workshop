# Включи автоодобрение команд в Hermes

Настрой в моём текущем профиле Hermes постоянное автоодобрение команд: `approvals.mode: "off"`. Выполни настройку сам, затем проверь результат. Не ограничивайся объяснением или списком команд для меня.

## Порядок действий

1. Определи установленную версию Hermes, активный профиль и путь к его конфигурации. Используй `hermes config path` в контексте текущего профиля; учитывай `HERMES_HOME`. Не меняй другие профили и не переключай профиль глобально.
2. Проверь поддержку `approvals.mode` по справке установленной версии и официальной документации: https://hermes-agent.nousresearch.com/docs/user-guide/security . Если Hermes не установлен, настройка не поддерживается или активный профиль нельзя определить однозначно, сообщи конкретную причину и остановись.
3. Перед изменением коротко предупреди: автоодобрение убирает запросы подтверждения потенциально опасных команд, поэтому ошибочная команда может изменить или удалить данные без дополнительного вопроса. Не подменяй запрошенный режим на `smart`.
4. Сохрани прежнее значение `approvals.mode` и локальную резервную копию конфигурации с ограниченными правами доступа. Не выводи полный конфигурационный файл и не отправляй резервную копию в чат: в них могут быть секреты.
5. Выполни штатную команду для текущего профиля:

   ```bash
   hermes config set approvals.mode off
   ```

   Для именованного профиля используй штатный флаг `--profile` с установленным на первом шаге именем. Не угадывай имя и не применяй изменение к профилю по умолчанию вместо активного.

   Если требуется точечное редактирование YAML, сохрани значение именно как строку:

   ```yaml
   approvals:
     mode: "off"
   ```

   Меняй только `approvals.mode`. Не заменяй весь конфигурационный файл этим фрагментом.
6. Прочитай изменённое поле обратно. Убедись, что его значение — строка `off`, а остальные настройки сохранены. Не проверяй автоодобрение удалением файлов, запуском загруженных скриптов или другими опасными действиями.
7. Уточни по установленной версии, когда изменение начинает действовать. Различай сохранённую настройку и проверенное применение в работающем процессе. Не перезапускай приложение или шлюз без необходимости и согласования.

Если инструмент или среда требуют подтверждения самого изменения, запроси его штатным способом. Не обходи отказ инструмента, ограничения среды или правила более высокого приоритета.

## Что не менять

- Не отключай встроенный безусловный список запрещённых команд и не удаляй `approvals.deny`.
- Не меняй права ОС, авторизацию сервисов, защиту секретов и отдельные подтверждения MCP или интерфейса.
- Не редактируй `SOUL.md` и другие инструкции. Правило из `safety-rule.md` о подтверждении отправок, публикаций и изменений во внешних системах должно сохраниться.
- Не устанавливай дополнительное ПО и не меняй исходный код Hermes ради этой настройки.
- Не используй `/yolo` как замену постоянной настройке: это переключатель состояния, а задача — сохранить `approvals.mode: "off"` в нужном профиле.

## Отчёт после выполнения

Коротко сообщи:
- какой профиль изменён;
- прежнее и новое значение `approvals.mode`;
- результат обратного чтения;
- проверено ли применение в текущем процессе или только сохранение на диске;
- где находится локальная резервная копия;
- точную команду возврата прежнего режима для этого профиля.

Для включения ручных подтверждений используется `hermes config set approvals.mode manual`. При объяснении отмены учти: отдельно включённые `--yolo`, `/yolo` или `HERMES_YOLO_MODE=1` тоже потребуется отключить. Не утверждай, что одного изменения конфигурации достаточно, если действует такое переопределение.

Если настройку выполнить не удалось, сообщи, что осталось неизменным и какое действие требуется от меня. Не пиши «готово» без проверки.
