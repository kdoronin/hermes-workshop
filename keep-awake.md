# Не давать компьютеру уснуть во время работы Hermes

Модуль необязателен. Чтение файла не включает запрет сна. Настраивай его только после выбора пользователя и согласования режима.

## Что предложить

Объясни: если компьютер уснёт, локальный Hermes может перестать отвечать и выполнять задания по расписанию. Запрет автоматического сна увеличивает расход батареи и электричества; он не заменяет работающий шлюз и не защищает от отключения питания или интернета.

Одним вопросом предложи выбрать:
- временно на согласованный срок;
- пока работает выбранный процесс Hermes;
- постоянно после входа в ОС, только при отдельно согласованной схеме;
- не включать.

Рекомендуй ограниченный срок на компьютере, подключённом к питанию. Не выбирай бессрочный режим за пользователя. Отдельно уточни политику работы от батареи. Не сохраняй экран включённым, если этого не просили.

## Общий порядок

1. Определи реальную ОС и машину, где работает Hermes. При удалённом сервере или контейнере запрет сна локального ноутбука может не относиться к этой установке. Не управляй другой машиной без разрешения.
2. Проверь питание, действующие запреты сна и наличие штатных средств. Не меняй глобальные настройки питания, блокировку экрана, выключение дисплея, поведение крышки, критически низкий заряд и кнопки питания.
3. До запуска покажи режим, срок, затронутый процесс и способ остановки. Пользовательский выбор конкретного режима разрешает только этот режим.
4. Запусти ровно один собственный ограниченный процесс штатным инструментом фоновых процессов. Сохрани его идентификатор, точную команду и конец срока в локальном служебном файле выбранного профиля. Не записывай секреты. При повторной просьбе сначала проверь существующий процесс; не запускай дубликаты.
5. Проверь процесс и системный индикатор запрета сна. Живой процесс без подтверждённого запрета не считается успехом. Не проверяй намеренным усыплением рабочего компьютера.
6. При остановке заверши только собственный проверенный процесс. Не используй `killall`, не завершай все экземпляры `caffeinate`, `sleep`, Python или Hermes.
7. Сообщи, что запущено, что проверено, когда закончится и как отменить. Не обещай работу при закрытой крышке или ручном усыплении.

## macOS

Сверь параметры по `man caffeinate`. Для автоматического сна системы используется `-i`; `-d` удерживает дисплей и в этой задаче не нужен.

Ограниченный пример на два часа; используй его только если согласован именно такой срок:

```bash
/usr/bin/caffeinate -i -t 7200
```

Для привязки к проверенному процессу шлюза:

```bash
/usr/bin/caffeinate -i -w HERMES_PID
```

`HERMES_PID` — обозначение, замени его фактическим проверенным PID. Не привязывайся к краткоживущему диагностическому процессу. При перезапуске шлюза привязка к старому PID закончится.

Проверяй `pmset -g assertions`: нужный `PreventUserIdleSystemSleep` должен принадлежать созданному процессу. Проверяй питание через `pmset -g batt`. Режим `-i` не ограничен питанием от сети: если пользователь не разрешил батарею, не запускай его на батарее и не обещай автоматической остановки при отключении зарядки без отдельного проверенного наблюдателя.

Для постоянного режима сначала покажи отдельный план: пользовательский LaunchAgent, точный исполняемый файл, политика питания, отсутствие дубликатов и полная отмена. Создай его только после отдельного выбора, прочитай plist обратно и проверь службу, процесс и assertion. Не меняй `pmset` глобально и не добавляй автозапуск только потому, что пользователь выбрал временную настройку.

## Linux с systemd

Проверь `systemd-inhibit --help` и доступ к пользовательскому сеансу logind. Ограниченный пример:

```bash
systemd-inhibit --what=idle --mode=block --who=Hermes --why="Hermes temporary work" sleep 7200
```

Параметр `idle` ограничивает автоматическую обработку простоя; фактическая среда рабочего стола может использовать собственный механизм. Проверь `systemd-inhibit --list` и поведение системы. Не заявляй, что запрет гарантирован только потому, что команда запущена.

Если требуется `--what=sleep`, объясни, что этот запрет шире и может затронуть ручную попытку suspend. Не добавляй его без отдельного согласия. Не блокируй `shutdown`, кнопки питания или крышку. Не используй `sudo` ради обхода отказа. Если штатный механизм среды отличается, изучи его официальную документацию и согласуй минимальное изменение либо честно отложи настройку.

Для постоянного режима нужен отдельно согласованный пользовательский сервис с проверкой питания и отменой. Не устанавливай системную службу по умолчанию.

## Windows

Предпочитай временный процесс, который вызывает штатную функцию `SetThreadExecutionState` с `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` и снимает требование перед завершением. Не добавляй `ES_DISPLAY_REQUIRED` или `ES_AWAYMODE_REQUIRED` и не меняй схему `powercfg` глобально.

Следующий самодостаточный пример предназначен только для Windows с Python. Сохрани его в выбранном профиле как служебный скрипт и запусти в отдельном процессе с согласованным числом секунд. Не запускай на другой ОС.

```python
import argparse
import ctypes
import sys
import time

parser = argparse.ArgumentParser()
parser.add_argument("seconds", type=int)
args = parser.parse_args()
if sys.platform != "win32":
    parser.error("This helper requires Windows")
if args.seconds <= 0:
    parser.error("seconds must be positive")

set_state = ctypes.windll.kernel32.SetThreadExecutionState
set_state.argtypes = [ctypes.c_uint]
set_state.restype = ctypes.c_uint
ES_CONTINUOUS = 0x80000000
ES_SYSTEM_REQUIRED = 0x00000001
if not set_state(ES_CONTINUOUS | ES_SYSTEM_REQUIRED):
    raise ctypes.WinError()
try:
    print("System idle sleep inhibited for a bounded interval", flush=True)
    time.sleep(args.seconds)
finally:
    if not set_state(ES_CONTINUOUS):
        raise ctypes.WinError()
```

Проверь реальный вызов функции на целевой Windows и, если доступно, соответствующее требование через `powercfg /requests`. Не считай проверку синтаксиса на другой ОС проверкой запрета сна. Срок действия ограничен жизнью этого процесса. При отсутствии Python не устанавливай его молча: предложи проверенное штатное средство или отложи модуль.

Постоянный режим через планировщик заданий требует отдельного согласования пользователя, срока/условий, поведения на батарее и точного способа удаления задания.

## Добавить правило помощнику

После выбранной и проверенной настройки добавь в `SOUL.md` активного профиля только недостающее правило: «При длинной локальной задаче проверяй, может ли сон компьютера прервать работу. Предлагай ограниченный запрет автоматического сна; запускай его только в согласованном режиме, проверяй и снимай собственный запрет после завершения. Не отключай блокировку экрана и защитные режимы питания».

Если пользователь выбрал «не включать», ничего не запускай и не добавляй правило о постоянно включённом режиме. Изменения живой установки преподавателя при подготовке этого репозитория не требуются.
