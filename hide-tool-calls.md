# Скрывать вызовы инструментов

Необязательная настройка для тех, кому мешают технические сообщения о работе Hermes. Выполняй только после выбора текущим пользователем; чтение инструкции не разрешает изменений.

## Что меняется

Hermes продолжает пользоваться инструментами, но перестаёт показывать служебные строки с их вызовами в выбранном интерфейсе. Ответы, необходимые уточнения, ошибки и запросы разрешения сохраняются. Эта настройка не удаляет журналы, не скрывает данные от поставщика модели и не меняет права инструментов.

Это встроенная настройка отображения, отдельный навык и изменение `SOUL.md` не нужны. Автоодобрение команд настраивается отдельно в `hermes-auto-approve.md`; скрытие вызовов само по себе ничего не разрешает.

## Порядок настройки

1. Определи версию Hermes, ОС, активный профиль и интерфейс пользователя: например, Telegram, другой мессенджер или терминал. Учитывай `HERMES_HOME` и именованные профили. Не меняй чужие профили и не считай Telegram обязательным.
2. Загрузи `hermes-agent`, если доступен. Проверь параметры отображения по установленной версии и официальной документации. Если настройка не поддерживается, предложи отложить модуль; не изменяй исходный код или набор инструментов ради скрытия строк.
3. Объясни выбор: «Скрыть технические вызовы только здесь или во всех интерфейсах этого профиля?» Используй уже данный выбор; не задавай вопрос повторно. По умолчанию предлагай только текущий интерфейс, без изменения других каналов. До согласия только читай настройки.
4. Сохрани прежнее значение, факт отсутствия поля и локальную резервную копию конфигурации с ограниченными правами. Прочитай только нужные поля, не выводи конфигурацию целиком. Проверь платформенные и устаревшие переопределения, способные изменить результат.
5. Для выбранной платформы используй поддерживаемое поле `display.platforms.<platform>.tool_progress`. Пример для Telegram, только если выбран именно он:

   ```bash
   hermes config set display.platforms.telegram.tool_progress off
   ```

   Для именованного профиля используй штатный флаг `--profile` с фактическим именем. Другую платформу подставляй только по поддерживаемому ключу своей версии. Не выполняй Telegram-пример для пользователя другого интерфейса.

6. Если пользователь выбрал терминал либо все интерфейсы профиля, проверь поддержку общей настройки:

   ```bash
   hermes config set display.tool_progress off
   ```

   Общий параметр может влиять на несколько интерфейсов. Для выбора «только терминал» сначала проверь платформенное разделение в своей версии; если его нет, объясни расширение действия и согласуй его либо оставь настройку без изменений. Для «всех интерфейсов» проверь существующие платформенные переопределения: они могут иметь приоритет над общей настройкой. Меняй только согласованные поля.

7. При точечной правке YAML сохраняй значение как строку `"off"`. CLI некоторых версий записывает `off` как логическое `false`; это допустимо только после проверки, что установленный обработчик отображения понимает его как скрытие вызовов. Иначе точечно исправь поле на строку. Не заменяй весь файл этим фрагментом:

   ```yaml
   display:
     platforms:
       telegram:
         tool_progress: "off"
   ```

8. Прочитай изменённое поле обратно, проверь тип и фактический приоритет настроек. Сверь прочие поля с прежним состоянием. Не меняй `approvals.mode`, правила безопасности, разрешения MCP, доступность инструментов, предупреждения или сохранение журналов.
9. Проверь по своей версии, когда настройка применяется. Некоторые интерфейсы имеют сессионное переопределение через `/verbose`; не отправляй команду-переключатель вслепую и не меняй его без понимания состояния. Не утверждай, что сохранённое значение уже загрузил работающий процесс. Перезапуск шлюза требует согласования и не должен обходить запрет перезапуска из его собственной сессии.
10. Предложи безопасную проверку: прочитать один специально созданный учебный файл без личных данных и ответить по его содержимому. Убедись по реальному результату, что инструмент выполнился. Видимость служебных строк проверь в выбранном интерфейсе, при необходимости попроси пользователя подтвердить отсутствие строк. Не выполняй опасную команду ради проверки запроса разрешения. Если видимость проверить нельзя, укажи отдельно: значение сохранено, отображение ещё не проверено.

## Отмена и итог

Верни прежнее значение в том же профиле и интерфейсе; если поля до настройки не было, удали только добавленное поле. Не включай `all` принудительно, если прежде использовалось другое значение. Учти сессионные и платформенные переопределения, сохрани последующие пользовательские изменения. Проверь обратным чтением и сообщи, нужна ли новая сессия.

В отчёте назови профиль, выбранный интерфейс, изменённые поля, результат проверки и способ возврата. Отдельно подтверди, что режим одобрения и права инструментов не менялись.
