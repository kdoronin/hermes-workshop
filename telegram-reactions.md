# Реакции Telegram: сообщение принято, обработка завершена

Этот модуль включается только после выбора пользователем. Чтение файла не разрешает менять настройки.

## Зачем

Показывать на входящем сообщении состояние обработки: 👀 — Hermes начал работу; 👍 — ответ доставлен; 👎 — обработка завершилась ошибкой. Это индикатор шлюза, а не доказательство выполнения всех требований задачи и не отметка о прочтении человеком.

Это настройка встроенной возможности Hermes, а не новый навык. Не создавай навык и не редактируй исходный код ради её включения.

## Выполни настройку

1. Убедись, что пользователь выбрал именно реакции. Определи активный профиль, установленную версию и работающий Telegram-шлюз. Если Telegram не подключён, предложи отложить модуль; не создавай нового бота автоматически.
2. Загрузи `hermes-agent`, если доступен. Проверь поддержку по официальной документации и коду установленной версии. В современных версиях поддерживается `TELEGRAM_REACTIONS=true`; конфигурационное поле и приоритет окружения могут различаться между версиями.
3. Найди `.env` выбранного профиля через штатные средства Hermes. Прочитай только относящееся к реакциям значение. Не выводи файл целиком, токены и секреты. Учитывай переменную в окружении уже работающей службы: она может переопределять файл.
4. До записи сохрани локальную резервную копию с ограниченными правами, прежнее значение и факт отсутствия поля, если его не было. Не копируй конфигурацию из чужого профиля.
5. После проверки поддержки добавь или обнови единственную строку:

   ```dotenv
   TELEGRAM_REACTIONS=true
   ```

   Сохрани остальные строки без изменений. Не создавай дублирующиеся определения. Если версия использует только YAML, найди точный поддерживаемый путь в её документации и измени только соответствующее поле. Не угадывай путь по старому примеру.
6. Проверь значение обратным чтением без вывода секретов. Выясни, когда оно применяется к работающему шлюзу. Не перезапускай шлюз из собственной активной сессии в обход запрета инструмента. При необходимости согласуй короткий перерыв и попроси пользователя выполнить штатный перезапуск нужного профиля.
7. Попроси прислать новое нейтральное сообщение, например «Ответь одним словом: проверка». Проверь переход 👀 → 👍 на этом сообщении по доступным журналам и наблюдению пользователя. Не ставь обе реакции вручную: это проверило бы Bot API, но не жизненный цикл шлюза.
8. Если успешной проверки нет, раздели состояния: настройка сохранена; шлюз перечитал её; переход реакций наблюдён. Не проверяй 👎 намеренным сбоем рабочего шлюза. В группах ограничения реакций могут мешать их показу.

## Отмена

Верни прежнее значение в выбранном профиле; если строка была добавлена впервые, удали только её. Проверь другие переопределения. Укажи, потребуется ли перезапуск. Не отключай реакции другого профиля.

## Итог

Сообщи профиль, что изменено, результат проверки, что осталось проверить и способ отмены. Не называй 👍 подтверждением приёмки документа, оплаты или завершения проекта.
